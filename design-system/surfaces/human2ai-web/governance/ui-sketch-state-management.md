# UI 界面状态管理

本次沿用 UI 草图工作台的紧凑状态标签方向，在本地 UiSketchStateTabs 中组合 BasicButton 与 Ant Design Dropdown/Input/Modal。共享 TabSwitch 的字符串 label、至少两项约束及选择回调不支持状态菜单、单状态管理和长按排序；未修改同步的 vendor 文件。组件保持 candidate，不声明新的已批准视觉基线。

- 标签 hover 或键盘 focus 时显示右侧三点按钮。菜单顺序：新建状态、重命名、删除状态。
- 标签按钮高 24px，文字上下内边距为 0，状态条上下留白各 2px。
- 新建复制所操作状态的几何及显示状态，插入其后并选中。重命名去除首尾空白，名称最长 100 字符。
- 删除必须确认，至少保留一个状态；删除当前状态后切换到相邻状态。
- 按住标签 350ms 后可拖动；浮动标签和插入线提供反馈，松手提交一次排序。Esc、指针取消、丢失捕获、失焦或状态集合/选择变化取消拖动。
- 方向键、Home/End 切换，Ctrl+Shift+方向键排序。状态条使用 toolbar 与 aria-pressed，允许选择按钮与菜单按钮并存。
- 状态名称、默认编号和顺序随现有草稿自动保存。复制菜单同步名称及顺序，状态过渡提示词覆盖相邻状态对。
- 旧草稿默认解析 start 和 stages。删除 start 后顶层节点仍是共享内容和内部几何基准，不再作为可编辑或导出的状态；其余完整快照不变。

验证记录：

- ui-sketch-state-tabs 单元测试覆盖旧草稿兼容、重命名、排序、复制快照、删除边界、非法元数据、旧调用方重建 end。
- 导出测试覆盖多状态顺序、用户名称及删除到单状态；API 测试覆盖名称、顺序和删除结果的保存/读取往返。
- Chromium 中 Interactions Story 通过；覆盖菜单首项、重命名、新建选中、键盘排序、350ms 长按排序及删除。长按使用合成 Pointer Events，Story 单独替代指针捕获以适配合成事件。
- Chromium axe 检查状态条无违规项；单状态菜单删除项 aria-disabled=true。
- 长名称在 1024、1280、1536px 桌面容器约束下检查省略和内部横向滚动；实际工作台已检查紧凑状态条。
- i18n、领域基线、YisiUI doctor、类型检查、相关测试、Storybook 和 Next 生产构建通过。
