# 构图文字区域四角轮廓

复用现有 CompositionCanvas、CanvasNode 的常规移动/缩放/旋转和画布指针捕获。查询 corner 能力没有独立资产；CanvasNode 的包围框缩放和构图动势线双点控制不承担文字轮廓语义。因此四角手势保留在 CompositionCanvas，作为现有组件的本地扩展，不新增通用变形组件，不修改同步 vendor。

选中单个文字区域，按住 Ctrl 显示四个角点，拖动一个角点时其余角点固定。角点可聚焦并用方向键微调，Shift 加大步长。释放 Ctrl 后，已聚焦的角点保留到焦点离开；多选、只读与参考外观不提供轮廓控制。普通八向缩放继续缩放整个轮廓。手柄维持屏幕像素尺寸，并置于内容和既有控制层上方。

角点是文字整体外轮廓的意图，不指定字体或字形扭曲。内容占位线在多边形内部横向排布，再随节点旋转；编辑、参考视图与 SVG/PNG 导出保留同一轮廓。现有说明/显示文字/备注 Tooltip 保持原行为；节点说明不进入提示词，也不新增轮廓提示词段落。复用文字区域命名，新增中英文编号角点名称和按需操作帮助。

领域比较：UI 草图几何整理负责整数像素矩形，构图普通面积块负责矩形、三角形和椭圆；本能力仅归构图文字区域，注册为 local composition.text-region-outline。corners 按顺时针顺序存储节点旋转前包围框内的四个归一化点；宽高和旋转继续使用原模型，实际面积按四点多边形计算。交叉、凹陷或退化轮廓拒绝，拖拽保留最近一次有效结果。缺省 corners 的旧草稿仍为矩形，保持其数据和指纹。移动、缩放、旋转和复制保留归一化轮廓；主动切换固定长宽比会恢复常规形状。

布局状态独立保存 corners，继续委托 capture.named-states；会话版本保存和手势合并撤销复用 capture.draft-versioning、capture.canvas-edit-history，既有消费者和共享契约不变，不新增路由、数据库表或保存流程。构图精修允许原有位置和尺寸调整，但保留轮廓比例。

验证入口：composition-text-outline 单元测试、composition-sessions 保存/恢复集成测试、CompositionCanvas 的 TextRegion Story。覆盖旋转后的独立拖角、无效拖动、尺寸与面积、复制、状态切换、保存恢复、参考图标记、整次拖拽撤销/重做及双击编辑。拖动保留抓取位置相对角点的偏移；未达到 3px 拖动阈值的点击不修改轮廓。Story 同时验证普通边缘缩放保留归一化轮廓。

2026-09-27 正文绘制扩展：沿用显示文字字段及中英文语义，填入正文后由 composition/render.ts 统一绘制，逐行匹配区域宽度，整个文字块匹配区域高度，保留显式换行与旋转，并受既有四角轮廓裁切；空白仍绘制占位线。编辑、只读参考、悬停、复制、会话引用与 SVG 导出委托同一实现。比较了 CanvasText 的自然字号布局，该组件不承担按区域宽高拉伸的构图语义，因此不扩展通用文字 API。PNG 的 librsvg 忽略 textLength，由 Node 专用 raster.ts 适配器以 Pango 测量字宽并生成等效横向缩放；不把服务端依赖带入浏览器。沿用现有默认字体，跨操作系统的字体回退仍可能不同。
